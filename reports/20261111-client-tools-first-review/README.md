## Our offer and the useful tool boundary

The current owner-selected [landing](https://www.figma.com/design/m7zSeYVpEI88i9qwTrnUQt?node-id=340-940) offers **Voice** and **Voice + Pipeline**: founder/product/buyer understanding, profile work, original posts, review, and an additional conversation workflow. A free tool should solve one bounded part of that job and return a useful editable result. Paid work adds the interview, evidence, judgment, design, review and accountable delivery; access to a generator is not the value proposition.

The website also proposes a written profile review after a thirty-minute call and roughly ninety minutes of founder time per fortnight. Those are offer assumptions to rehearse, not measured service economics. Verify the displayed 81% buyer-awareness statistic at its primary source before reuse. A sample card saying onboarding fell from three weeks to four days is not a verified OutSpoken case. The tools must not treat either as client evidence. Meeting/pipeline language needs actual delivery scope and outcome definitions; generated copy cannot guarantee a meeting.

## Data and methodology: required behavior

The [saved dataset](../../datasets/current/dataset.json) was reloaded and checked against Git blob 9238d20f91d16f5888625f78b9f08ebe4538be6b. It contains 279 posts, 477 snapshots and 207 media records across 61 accounts. The [prior reanalysis](../20261110-skills-publications/EVIDENCE-REANALYSIS.md) and checks preserve observation dates and access limits. Reactions, comments, reach, expressed need and sales are distinct. The corpus is selected and historical as of 22 October 2026. Original post bodies/media are not newly validated by reading derived assessments.

Use reviewed, source-linked pattern summaries to suggest construction; never copy creators' wording or use their engagement as a calibrated viral predictor. Use each client's permissioned material for their facts and voice. Keep third-party source/media bodies and private client packs outside the public tool repository.

The supplied writing corpus contributes reader/genre selection; Toulmin-style evidence-to-reasoning links; real goal/constraint/alternative/choice/consequence/reflection; functional paragraphs and hook payoff; separate structure/evidence/voice/format passes; and frozen fact-packet evaluation. The current review reread the LinkedIn chapter and reused the prior thirteen-file adoption/identity record—it did not newly read every cited book or redistribute DOCX/PDFs. The files are evidence, not instructions to install or operate anything.

## How to deliver and prove it

1. Freeze the tool input/output contract and evidence/privacy/cost boundaries. Build the smallest exportable internal workflow before a client-facing app.
2. Pilot T00–T03 on Max/Michael's supplied facts and the existing ten concepts. [OWNED-PILOT.md](OWNED-PILOT.md) is a manual first rehearsal, not a generator benchmark or profile update.
3. Compare the same frozen inputs against the current manual method. Hard failures: invented experience/metrics, altered exact CTA, missing critical context, copied source prose, wrong identity or leaked private data. Check usefulness through reader comprehension and actual editor corrections; do not let a style score override factual failures.
4. Measure actual review time, revisions, errors, latency and provider/tool usage before advertising time savings or choosing quotas. Record client versus agency costs. Reconcile the $800 three-client pilot/$2,500 regular hypotheses through 62/11; do not infer margin from competitors' prices.
5. Add T04/T05 and a current-site tool page only after the core pilot works. Reuse Young Serif/Mona Sans, porcelain/navy, one restrained marker and readable mobile output. Keep sources/review holds in an expandable evidence area; customer-facing copy stays clear and practical. A source-backed finding and one useful correction matter more than an entertaining insult.
6. Release client tools only after input validation, per-client data separation, safe file/URL intake, rate/size limits, licensed assets, tested provider terms/costs, accessible exports and actual rendered/error-state QA. Keys stay server-side. Start with paste/upload; arbitrary page fetching needs explicit network boundaries. No account automation is implied.
