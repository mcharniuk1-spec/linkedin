# Working-example cards and retrieval

A knowledge card is a compact original analysis linked to an exact source. It is not permission to redistribute a post or a substitute for inspecting evidence when a new claim depends on it.

## Writing card

Retain source ID/URL, author, publication and capture dates when known, version/hash, actual reading modality and completeness limit. Code the reader problem, hook function and promised payoff, main-text progression, evidence/proof function, reasoning, emphasis, ending/audience response, transferable structure, human-required facts and scope limit. Do not infer motives, exact sequencing or jokes from a locator or prior summary.

## Visual card

Retain the linked post identity and separate the listed media file's hash from the actual inspected still, poster or sampled-sheet hashes. State which frames/asset were viewed. Code attention, hierarchy, semantic grouping or sequence, numeric use/denominator, object/scene function, caption relationship, accessibility and original application. Mark source-media reuse as uncleared unless actual rights establish otherwise. A still poster is not a watched video; sampled sheets are not a continuous performance or audio review.

## Scope and transfer

Keep commercial service competitors, professional reference creators, adjacent tool vendors and prospects in separate populations. A service page supports its described offer/process; it does not show that provider's LinkedIn hook or prove delivery effectiveness. State all expected IDs and missing/duplicate/unreadable examples. Preserve weak or contrary examples already present. A selected historical set does not establish a current trend or optimal format.

For each proposed post, record the reader job, selected card IDs, adopted function, original adaptation, source/claim links, required human material and remaining limits. Do not force a reference visual into an unrelated idea. Agent preparation can automate joins, retrieval and draft scaffolds; genuine author experience, current capabilities, recipient relevance and final review need the appropriate human/source evidence.

Monthly questions determine audience decisions and source availability. Weekly questions choose actual content and review work. Post questions resolve only the missing truth, stance or example needed for that draft. Return prefilled facts separately from questions; do not send the founder the full template every time.

Validate knowledge joins and all internal targets against the expected source set. Structural completeness, a Git push and a readable card do not demonstrate audience lift, writing quality or automatic runtime retrieval. Existing graph/vector indexes remain stale until a scoped rebuild is actually executed and checked.
