# LinkedIn access and the 100-post gap

The existing LinkedIn application credentials were checked privately. They contain a client ID and client secret; they do not contain an access token or refresh token. The existing callback is `https://www.arch-flow.dev/api/linkedin/callback`; it returned HTTP 200 when checked without OAuth parameters. That verifies the route is reachable, not that an authorization exchange or API read has succeeded.

The app owner previously reported `r_verify`, `r_profile_basicinfo`, and `w_member_social`. No approved post-reading scope or member access token has been verified. The collector's official API route remains disabled pending an access-controlled API-specific store and retention/deletion implementation. The public LinkedIn source is on a security-challenge hold. Search links and snippets do not establish current post content, engagement, or trending status. The target of **100 newly collected, current LinkedIn posts across at least 10 top-performing accounts has not been met**.

## What the app owner can do

1. Open [LinkedIn Developer Portal — My Apps](https://www.linkedin.com/developers/apps) and select the existing application.
2. In **Products**, request the Community Management API if available, and wait for LinkedIn's approval. See [LinkedIn's access and permission guide](https://learn.microsoft.com/en-us/linkedin/marketing/increasing-access).
3. Once approved, inspect the **Auth** tab and tell the project agent which approved read permission names are visible. For eligible organization posts, the relevant permission is `r_organization_social`; request other scopes only when the exact intended use needs them and the app is approved for them. Do not send a client secret, access token, refresh token, authorization code, or callback URL containing query parameters in chat.
4. Tell the agent which specific owned or consenting Page is in scope and the consenting member's Page role. LinkedIn requires an eligible role for organization-post retrieval. A consenting member must then complete the approved OAuth flow. See [Posts API permissions](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/posts-api) and [LinkedIn's authorization-code flow](https://learn.microsoft.com/en-us/linkedin/shared/authentication/authorization-code-flow).
5. Before enabling the API collector, the project must complete and test separate, access-controlled API storage, applicable consent and role checks, and data-type-specific retention and deletion under the [LinkedIn API data storage requirements](https://learn.microsoft.com/en-us/linkedin/marketing/data-storage-requirements). Approval and a token alone do not complete that engineering work.

Community Management Development tier has application and member call limits; API approval does not guarantee a daily yield of 100 posts. Organization permissions cover eligible authorized Pages, not universal searches or unrestricted reads of competitors, unrelated members, or all employees. Restricted member content requires its own explicitly granted access. Do not work around a challenge, login boundary, access denial, or rate limit.

## Other permitted data paths

- **Owner-provided exports:** An account owner or consenting client can provide their own analytics through a private, agreed channel. LinkedIn documents [member combined analytics exports](https://www.linkedin.com/help/linkedin/answer/a701208) and [Page analytics exports](https://www.linkedin.com/help/linkedin/answer/a551206). Combined analytics may be aggregate rather than post-level. The current importer accepts selected CSV/XLSX schemas; a real LinkedIn export has not yet been validated, and LinkedIn's Page guide describes XLS, which the current importer does not accept directly. Check format, consent, rights, retention, and field-level coverage before import.
- **Rights-cleared material:** A creator or account owner may supply an expressly authorized dataset or publications and media, with provenance, use rights and permitted handling recorded. Verify any counters and observation dates independently; do not convert missing figures into zero.
- **Licensed providers:** Consider a provider only after confirming that its contract and source rights permit the required collection, storage, analysis and display, and after the owner approves any cost. A provider's claim of coverage is not evidence that the requested rights or 100-post target are met.

[Tech.eu Funding Explorer](https://funding.tech.eu/llms.txt) supplies funding and company-discovery signals. It does not provide LinkedIn post performance, prove a company is a qualified prospect, or establish buying intent. Exa/search-index results are candidate locators, not evidence of LinkedIn reactions or current trends.
