# LinkedIn writing and visual knowledge

Version 1.0 · 12 November 2026 · source-verified editorial knowledge; author and market outcomes are not certified by a schema check.

This index extends the existing writing knowledge namespace. It routes to the current owned methodology and concrete source cards rather than replacing them with a second writing framework.

## Start with the current job

1. Read the current author/buyer/service brief and [practical writing contract](practical-writing-contract.md).
2. Select a publication pattern from the existing [14-pattern library](../../../docs/linkedin-writing/PATTERN-LIBRARY.md). Topic, reader job, pattern, media format and voice are separate decisions.
3. Retrieve two relevant [writing examples](writing-examples.json) and, if a visual is useful, one [visual example](visual-examples.json). Inspect their source identity, actual modality, proof type, application and limit. Transfer a function; do not copy an author’s story or recognizable artwork.
4. Use [monthly strategy](templates/monthly-strategy.md),[weekly planning](templates/weekly-planning.md) and [one-publication intake](templates/publication-intake.md). Prefill from current evidence; ask the founder only for decisions or facts that are genuinely missing.
5. Follow the [automation and human-work map](automation-human-map.md). Human judgment supplies experience, stance and product truth; tools can prepare and verify much of the structure.
6. Freeze the caption revision, visual text, sources and review disposition together. The [native writing skills](../../../skills/) remain reusable; this knowledge supplies project-specific inputs.

## Skills and tool integration

`founder-content-writing` loads the author/buyer/voice packet before drafting. `linkedin-reference-pattern-review` reads source cards and coverage limits. `linkedin-publication-architecture` composes the hook, reasoning, structure and ending. Full humanization and fact-preservation check the wording; `brand-system-delivery` binds the final copy to visual slots and rendered review.

The task brief explicitly supplies this index, relevant card IDs and the selected intake template to those skills. This route is recorded in [AGENT-ROUTING](../../../docs/linkedin-writing/AGENT-ROUTING.md). Installed generic skill bundles were not modified or newly activated by this knowledge update. Tool 67 must receive the same versioned brief; a knowledge file is not a deployed client app.

[Knowledge validation](validation.json) checks expected IDs, source joins, modality/rights fields, internal links and publication references. It does not validate an author’s memories or establish audience lift. The existing writing Graphify graph predates these cards; no automatic graph/vector rebuild or semantic-performance claim is made.
