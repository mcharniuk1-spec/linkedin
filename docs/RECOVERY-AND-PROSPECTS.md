# Checkpoint viewer and prospect discovery

To project the latest authenticated production checkpoint, use a private machine with GitHub read access and the owner's separately protected state-key file. Set `COLLECTOR_STATE_KEY_FILE` to that file without publishing its value, then run:

```sh
python -m research.collector.latest_viewer --repository OWNER/REPO --output /private/directory/unique-view.json
python -m http.server 6078 --bind 127.0.0.1
```

Open `http://127.0.0.1:6078/research/permitted_viewer/` and select the snapshot. The command authenticates and verifies the checkpoint, decrypts it only in a temporary private directory, checks that the pointer did not change, creates a mode-0600 local JSON snapshot and removes the temporary directory. A changed checkpoint fails closed; retry with a new output file. The displayed snapshot is current at refresh, not continuously live. The JSON is plaintext private data: keep it outside Git and any served folder, and delete it when no longer needed. Temporary deletion is not secure erasure; use encrypted local storage. Do not upload the output or encryption key.

The collector uses [Tech.eu Funding Explorer](https://funding.tech.eu/llms.txt), using its free public API, for 90-day AI funding rounds at Seed, Series A or Series B in an explicit European-country allowlist. A one-time bootstrap reads at most one page per stage and may be truncated; source reports list truncated stages. Future incremental collection follows its `/changes` feed, persists its cursor, records removals, and can resume partial pages. It does not capture upstream in-place edits and is not a complete mirror. Displayed rows attribute Tech.eu Funding Explorer, link CC BY 4.0 and the source, and identify filtering. Each is a **pending prospect seed**, not an established B2B SaaS company, 10–50-person team, active LinkedIn account, buying signal, or expressed interest. Verify each independently before outreach or qualification. Exa, HN and RSS remain separate leads and are not LinkedIn performance data.

New, unchanged, unreviewed Tech.eu seeds expire after 180 days without a source observation. Reviewed or edited rows, legacy entries and ambiguous records are preserved. New managed Exa raw evidence expires no sooner than 30 days if it is not referenced elsewhere; its observation metadata and hash remain. Historic unregistered Exa objects, reviewed material, private snapshot copies and backups need their own retention review. Collector compaction runs only when eligible managed raw expires. Owner-export expiry is enforced on access/import or manually by the owner; an idle store is not automatically cleaned.

LinkedIn public collection is still stopped on the recorded security challenge. Never bypass it. The existing app's client credentials are not post-read permission: official organization posts require approved Community Management access, the appropriate `r_organization_social` scope, member authorization and an eligible Page role. The current app does not have verified post-read grants. API collection remains fail-closed until a separate API data store, agreement review and source/data-type retention controls are implemented. See [LinkedIn permissions](https://learn.microsoft.com/en-us/linkedin/marketing/increasing-access). Owner-provided exports are a separate manual source.

Each collection attempt keeps the actual source-hold failure visible, even when independent discovery succeeds. Encrypted artifact cleanup protects the active and previous pointers, uses creation time rather than opaque IDs, and declines deletion when ordering is ambiguous. GitHub scheduling is best effort. The 100-post/10-account goal remains unproven: search results and funding records do not count as collected posts.

Exa's tool result has its own hold, separate from LinkedIn. A manually dispatched workflow may use `reconcile_exa_false_hold=true` only after stored, hash-verified response evidence proves that the Exa hold resulted from an indexed result's wording instead of a provider denial. The reconciliation checks the hold reason, response, timing and top-level error status before it releases Exa. It does not change LinkedIn's hold or resume an HTTP denial. Leave the flag false for ordinary scheduled runs.
